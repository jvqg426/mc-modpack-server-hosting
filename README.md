## 你的整合包到底要吃多少内存

按人数分：3–5人，8–10G够用；6–15人，10–12G；15人以上，或者建了大量机器、区块加载器，12G起步再往上加2–4G。

三个来源给出的数字不一样，原因在测试场景不同，放在一起看更清楚：

- ATM10 的整合包页面写“推荐服务器内存12GB”，并注明在线人数多、机器和区块加载器多时可以再加2–4G。这是偏保守的口径，面向的是长期服。
- ATM10 开服教程给的是“内存10G+、带宽10Mbps”，这是最低可用的口径。
- 乌托邦探险之旅3.0（1.20.1、Fabric、505个模组）的教程建议“4核10G以上，最低不要低于4核8G”，并强调CPU要高主频高单核性能，原话是“高版本的java服很吃单核性能和内存，大型整合包更加吃性能”。

所以10G是这类大型整合包的公共下限，12G是稳态运行的建议值。如果你只开周末两三晚、同时在线不超过8人，10G那一档就能跑；如果打算7×24常驻、玩家会挂机造机器，直接上12G那档省得后期升级。

自己电脑开服的话，内存分配有一条硬规矩：分配量不要超过物理内存的50%。16G的机器最多给8G，给到12G会把Java进程杀掉，表现就是玩着玩着闪退。进游戏按F3看右上角的 Allocated Memory 和 Used Memory，长期超过80%说明给少了，长期低于30%说明给多了。

租面板服不用操心这条，面板给的是整台实例的内存，启动脚本里的 `-Xms6G` 和 `-XX:MaxRAMPercentage=95.0` 已经替你留好了余量。

## 版本链差一个，配置再高也进不去

整合包联机要对齐的是一串版本号，不是单个游戏版本：游戏主版本（比如1.21.1）、模组加载器及版本（NeoForge 或 Fabric 的具体版本）、MOD列表与每个MOD的版本、配置文件（config目录和脚本改动）。差一个都进不去，最常见的报错是 Mod Rejection，后面跟一长串不匹配的模组名。

ATM10 基于 Minecraft 1.21.1、用 NeoForge 加载器，约500个模组。它的服务端启动命令里的 NeoForge 版本号会随整合包版本变，这是前排教程里很少写、但直接决定能不能启动的细节：

| ATM10 版本 | 启动命令里的 NeoForge 版本 |
| --- | --- |
| V5.5 | 21.1.219 |
| V6.6 | 21.1.224 |
| V7.0 | 21.1.228 |

启动脚本的完整形式是 `java -Xms6G -XX:MaxRAMPercentage=95.0 @libraries/net/neoforged/neoforge/21.1.228/unix_args.txt`。你下的服务端是哪个版本，就把路径里的版本号换成对应的那个。用V7.0的服务端配V5.5的启动命令，服务端起不来。

Java 版本也要对。MC 1.18 到 1.20.4 用 Java 17 兼容性最好，1.12.2 及更老用 Java 8。ATM10 是 1.21.1，雨云面板环境里直接选 Java 21 就行，平台已经把运行时装好了，不用自己在服务器上折腾 JDK。

客户端这边还有一条：整合包要整包分发。用一个启动器导出整合包，或者打包压缩发给所有人，不要各自装MOD。手动一个个装MOD，十次有九次会漏，漏一个就是 Mod Rejection。

## 雨云面板服开ATM10：六步跑起来

购买路径是控制台“总览”或“云产品” → “购买游戏云” → 选 MCSM 面板 → 游戏类型选“纯Java环境” → 环境选 Java 21 → 选机型和配置 → 下单。

开服步骤按顺序走：

1. 记下端口映射。控制台会给一个端口，比如48652，内外端口保持一致，后面要填进配置文件。
2. 进面板的文件管理，上传服务端压缩包，选“解压到当前目录”，等它解压完。压缩包编码如果是GBK，解压时选GBK，否则中文文件名会乱码。
3. 打开 `server.properties`，把 `server-port=25565` 里的 25565 改成上一步的映射端口。顺手确认几项：`max-players=20`、`view-distance=7`、`simulation-distance=5`、`online-mode=true`（要正版验证就开）、`white-list=true`。
4. 打开 `启动脚本(可修改).sh`，清空内容，替换成对应整合包版本的启动命令。文件名不要改。
5. 回控制台点启动，等实例跑起来。
6. 用控制台显示的映射地址连接，形式类似 `ni.rainplay.cn:33333`，实际以你的控制台为准。

有两点容易踩：一是不要用 Windows 服务器开服，Windows 系统自身占用的内存和CPU更高，Linux 面板服更划算；二是端口映射的内外端口要一致，改完 `server.properties` 记得保存再启动。

## 更新服务端不丢档：只保留这些文件

整合包更新频繁，ATM10 从 V5.5 到 V7.0 中间隔了好几个版本。更新时不用整个目录覆盖，按这个清单来：

下载新版本服务端，关服，然后把旧服务端里除以下文件和文件夹之外的内容全部删除：

- `world` 文件夹（存档）
- `banned-ips.json`、`banned-players.json`
- `ops.json`、`whitelist.json`
- `server.properties`、`server_banlist_config.json`
- `usercache.json`、`usernamecache.json`
- `启动脚本(可修改).sh`（面板服千万别删这个）

然后上传新服务端压缩包解压，把启动脚本里的 NeoForge 版本号改成新版本对应的数字，再启动。存档、白名单、OP权限都保留，只有服务端程序换新。

这套流程在面板服上尤其要注意启动脚本：很多面板的启动项指向的就是这个 `.sh` 文件，删了就得重新配。

| 云主机自建 | 按公开促销价建模约100–300元/月 | 6人以上、要7×24常驻 | 要会命令行，首次部署半天起步；改MOD要走上传重启 |
